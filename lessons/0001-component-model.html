Lesson 1: Build Your First Component

Weekend 1, part 1. One win: a real React component running on your own computer.

A Next.js page is just a React component. If you can read a function and write HTML, you can edit any page. This lesson teaches the three ideas that unlock everything: components, props, and state. Per the official course, a page.tsx "exports a React component" — so a page is a function. Everything below is that same idea, in a reusable box.

Step 0 — Create the project

This one command makes a full Next.js + TypeScript starter. It is your blank canvas for every site you sell.

npx create-next-app@latest landing --ts --app
cd landing
npm run dev

Open http://localhost:3000. You see the default page — that is app/page.tsx, your first component.

Concept 1 — A component is a function

A component is a JavaScript function that returns JSX. JSX looks like HTML but lives inside JavaScript. Compare to what you already know:

You know HTML. JSX is HTML with two rules: (1) class becomes className, (2) most tags close themselves: <br />. You will not memorize these — the editor highlights them.
// A plain JS function you might write in Laravel/PHP:
// function heading($t) { return "<h1>$t</h1>"; }

// A React component (note the capital letter — required):
function Hero() {
  return <h1>Acme Plumbing</h1>;
}

Concept 2 — Props are inputs

Props are how you pass information into a component — exactly like a function argument. That means one Hero works for "Acme Plumbing" and "Bella Coffee" by passing a different title:

function Hero({ title }) {
  return <h1>{title}</h1>;
}
// <Hero title="Acme Plumbing" />
// <Hero title="Bella Coffee" />

The curly braces {title} are a JSX expression — "print the variable here". This is the bridge between your JS knowledge and the page.

Concept 3 — State makes it interactive

Props come from outside; state is memory inside a component. When state changes, the component re-renders. useState creates that memory:

import { useState } from 'react';

function Hero({ title }) {
  const [showDetails, setShowDetails] = useState(false);

  return (
    <section>
      <h1>{title}</h1>
      <button onClick={() => setShowDetails(!showDetails)}>
        {showDetails ? 'Hide' : 'Show'} pricing
      </button>
      {showDetails && <p>Book today for 10% off.</p>}
    </section>
  );
}
Read this line by line if it is new: useState(false) starts a memory slot as false. {showDetails && <p>...</p>} renders the paragraph only when showDetails is true. setShowDetails(!showDetails) flips it — and the button relabels itself automatically. That is reactivity.

Hands-on — make it yours

Create the file components/Hero.tsx and paste the TypeScript version below. The .tsx means JSX + TypeScript. 'use client' tells Next.js this component uses browser reactivity (state). The interface type-checks the title prop so typos crash at compile time, not in a client's browser.

'use client';

import { useState } from 'react';

interface HeroProps {
  title: string;
}

export default function Hero({ title }: HeroProps) {
  const [showDetails, setShowDetails] = useState(false);

  return (
    <section>
      <h1>{title}</h1>
      <button onClick={() => setShowDetails(!showDetails)}>
        {showDetails ? 'Hide' : 'Show'} pricing
      </button>
      {showDetails && <p>Book today for 10% off.</p>}
    </section>
  );
}

Now wire it into the home page. Replace app/page.tsx entirely with:

import Hero from '@/components/Hero';

export default function Home() {
  return (
    <main>
      <Hero title="Acme Plumbing — 24h Fast Service" />
    </main>
  );
}

Save both files. Your browser reloads. Click the button. If it does not reload, restart npm run dev.
